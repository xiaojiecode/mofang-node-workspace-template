# AI 意图路由

本模板把 AI 视为节点作者和平台操作代理。用户的自然语言先映射到一个明确的操作层级，再执行对应入口；不能把本地预览、平台保存、实例发布和真实运行合并成一个“完成”动作。

| 用户意图 | AI 行为 | 需要停下确认的边界 |
| --- | --- | --- |
| 讨论方案、审查现状 | 只读规范、源码、Schema、测试和 Git 状态，输出事实与方案 | 不修改文件，不访问外部写入接口 |
| 创建独立工程 | 使用 `init`，目标目录必须为空，生成指定预设和渲染器 | 目标路径、工程名或预设不明确时询问 |
| 在现有工程新增节点 | 使用 `node:new` 生成骨架，再读取合同和真实能力实现业务 | 节点编码、预设和面板渲染器不能猜测 |
| 编写或修改节点逻辑 | 读取 JS 节点规范、可信类型和能力双 Schema，默认本地 Mock | 输入输出、状态、人工动作、恢复和失败规则会改变行为时先确认 |
| 修改 Lit 面板 | 读取 `panels.json` 和 Lit 技能，修改源码并本地验证 | 不把页面展示逻辑改成业务执行逻辑 |
| 修改 Puck 面板 | 先 `lowcode guide/catalog/inspect`，使用带 revision 的语义操作，再 validate/preview | 冲突必须重读并合并，不能覆盖未知组件或绑定 |
| 预览页面 | 只生成本地 Mock 预览 URL，核对实际 revision 和交互 | 不保存页面、不调用真实能力、不宣称真实链路成功 |
| 验证本地产物 | 按风险运行 typecheck、build、verify、trial 或平台 doctor | 验证通过不等于平台保存、发布或业务验收 |
| 保存目录或面板 | 读取最新身份和 revision，分别准备并执行对应保存操作 | 目录、settings、business 必须分开确认和回读 |
| 发布已有实例 | 查询实例并使用明确 scope 和 targets | 不默认 `all_instances`，不把页面发布当执行定义更新 |
| 真实调用或试跑 | 使用同环境 client profile 和明确 workspace，保留原始回执 | 必须有明确授权；未知结果先核对，不能自动重发 |
| 同步模板 | 使用 `upstream sync`，保留本地提交并普通合并 | 不自动 reset、rebase、切分支、删除业务文件或推送 |
| 恢复同步记录 | 使用 `upstream recover` 补记已完成或已撤销状态 | 不重写文件、不重新合并 |
| 删除或重置工程 | 先核对目标路径、范围和当前 Git 状态，再执行用户明确授权的破坏性操作 | 不把历史提交、AGENTS.local.md 或缓存当作恢复依据 |

## 入口选择

- `npm run init -- --dir <目录> --name <名称>` 创建独立工程。
- `npm run node:new -- --code <编码> --preset <预设>` 在当前工程增加节点。
- `npm run lowcode -- <动作>` 只操作本地页面包和预览。
- `npm run platform -- <参数>` 访问平台 CLI；目录和 Schema 查询默认只读。
- `npm run upstream -- sync|recover` 管理模板合并状态。

`保存页面`、`发布页面`、`采用执行定义`和`启动新运行`是四个不同动作。用户只说“发布”或“运行”时，先确认具体对象和范围。

平台 CLI 的参数由 npm 转发时使用 `npm run platform -- --profile <名称> ...`；直接调用包装器时使用 `node tooling/cli.mjs platform --profile <名称> ...`。包装器会兼容一个多余的单独 `--`，但 AI 应优先使用上面的规范形式。
