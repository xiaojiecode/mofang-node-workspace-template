# 必须事件与验证证据

对每个必要人工事件记录：前置条件、实际入口、payload Schema、身份/修订、guard、outcome、下一等待和结束条件。不能只存在handler而页面无法触发。

逐个等待点核对节点状态：系统无可推进任务时不能停在running，人工等待呈现为waiting并显示原因与下一步；暂停、取消、失败、零结果和不选择都能到达paused/cancelled/failed/succeeded或明确的待处理。真实平台显示状态单独记录，未实际运行标未验证。

至少覆盖：正常提交、零结果、不选择结束、失败、unknown核对、过期选择、并发任务、输入关闭、候选待审核、审核后新增任务、finish与spawn同事件、暂停/取消竞态、网络回执丢失和刷新恢复。

验证初始投影可读取冻结用户设置且无须伪造商品；再执行范围内用户动作并接收真实到达，检查每次输入按来源规则解析，用户选择、既有 state 和节点设置未被覆盖。单节点试运行的范围外节点只读；全节点初始化失败不能启动业务。作者 Mock 不能证明平台的屏障、并发和恢复行为。

类型与Schema、fixture、真实Goja、真实平台ABI、隔离PostgreSQL、浏览器和实际业务分别记录。每项有退出状态、身份、mock范围和未覆盖内容；没有执行就写未验证。

角色与历史只读、来自实际上游的inputRefs、每阶段单次业务调用与完整子任务累计预算、真实answer绑定、动作结果不可被取消改写都不能因简化代码删除。模板改动还需空目录冷生成与隐藏技能发现。

预算用例按[作者规范](../../../../docs/authoring.md)覆盖完整阶段、互斥分支和有界轮询；同时验证预算刚好够用、用尽后消息免计及其它工具仍被拒绝。Mock 不模拟真实预算账本时必须明确标为未验证，不能据此声称平台规则已生效。

禁止为检查而清空共享库、改冻结历史、绕权限、自动重试未知业务或向真实平台提交未授权上架。
