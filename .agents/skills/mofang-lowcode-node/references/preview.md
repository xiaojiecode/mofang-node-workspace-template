# 预览和发布边界

预览使用共享 PageRenderer、工作流适配器和本地 Mock SDK，不挂编辑器。用户可试填、勾选、点按钮；修改组件、事件、数据源都通过 AI。

## 本地看效果

`lowcode preview` 只返回 URL，不启动服务。先确认端口是否占用，并核对已有服务属于哪个工程；启动命令见[使用说明](../../../../docs/lowcode.md#看效果和提出修改)。使用系统默认外部浏览器打开返回地址。

AI apply 后预览可跟随合法 revision；暂停跟随后需显式加载新版本，加载会重置试填。正常、空结果、读取失败和只读均需验证；设置的模拟保存/取消只操作试填草稿，不修改页面源文件或真实工作流配置。

| 核对对象 | 能证明什么 |
| --- | --- |
| `.page.json` 与 inspect / validate | 页面结构、引用及节点身份符合当前共享包合同 |
| 源码预览 | 当前页面配置在本地运行器、适配器和 Mock 下的交互 |
| build 后的 `?artifacts=true` 预览 | 构建产物能被本地运行器加载；构建后才反映最新源文件 |
| 后台回读 | 目标环境已保存指定执行代码及页面包 |
| 实际客户端验证 | 该部署宿主能加载页面并正确连接实际节点上下文 |

交付前核对标题、长文本悬停、窄视口与主操作可达性，记录浏览器错误、网络请求、页面版本。源码预览与 `?artifacts=true` 产物预览分别验证。Mock 成功不代表真实 Tool 执行、远端保存或发布成功。

## 上传前准备与回读

1. build/verify 通过后，读取目标环境的节点目录身份及修订，保存真实回读快照。
2. 使用 `npm run panels:prepare -- --code <编码> --surface <面板> --catalog-file <真实目录回读快照> --out <新请求文件>`。命令只生成正文，不发送请求；核对页面包与本次构建产物相同。
3. 上传前读取[平台请求结构与当前工具差异](../../mofang-js-node/references/platform-cli.md#puck-页面的后台请求结构)。目前工具生成顶层 rendererKey/config，后台接收 lowcode 对象；不能将 prepare 成功当成可直接上传的证明。沿用户授权处理请求适配，保留鉴权、目标与修订核对。
4. 保存 settings 后回读当前修订，再准备和保存 business。分别比较回读 config 与本地完整包，记录目录及页面修订；失败或结果未知时先回读，不盲目重发。

Puck 上传原生页面 JSON，不包成 Lit，也不附带 Lit viewSource/programSource。

## 发布与运行

保存目录页面后，新建节点实例使用目录当前页面；已有实例的页面更新需要显式发布范围。页面保存、面板发布、执行定义采用、工作流版本和新运行分别记录，具体区别见[接入说明](../../../../docs/lowcode.md#保存发布和运行的区别)。用户要求上传后台不等于要求启动真实采集。

正式 frontend 必须支持 settingsFormId 和当前包版本；不把新包降级塞入旧 runtime。交付给出实际工程和产物路径、本地预览地址、验证模式、上传环境及回读结果，未执行的真实链路明确标注。
