# 面板评审场景

围绕本次业务选择相关项，不强制每次做全量审查。问题记录具体页面、触发条件、用户影响及证据；不能只写“层级不佳”或给主观分数。

| 场景 | 看什么 | 操作应证明什么 |
| --- | --- | --- |
| settings 初次打开 | 标签、单位、默认值与来源 | 必填值可理解，草稿回调和宿主保存保持一致 |
| settings 修改后清空 | 数字 0、缺省/null、校验提示 | 清空不会变为合法 0，错误不丢失其它草稿 |
| business 等待任务 | 真实状态、当前对象、等待原因 | 订阅更新只渲染，不发起新任务 |
| 同一数据的状态刷新 | 就绪、核验、处理中、失败、恢复前后的几何与 DOM | 主区、列宽和滚动位置稳定；有效焦点/草稿保留；普通订阅不重播动画；错误仍可见可核对 |
| 零结果或无匹配 | 区分任务无结果与局部筛选无匹配 | 下一步符合已确认规则，不用假数据填充 |
| 候选审核 | 判断所需列、详情、选择范围 | 零选择、部分选择、分页选择含义明确 |
| 动作受理但 view 未变化 | 受理与实际结果分别反馈 | 按 eventId 跟踪 outcome，不能靠 view 变化判断成功 |
| 部分失败/修订冲突 | 对象旁结果、原有选择和输入 | 保留仍有效的交互，说明核对路径，不静默重发 |
| 网络断开后重开 | 已有动作、真实目标与修订 | 查询原结果，不新增 POST，不显示上一节点的结果 |
| 历史只读/无权限 | 原因和可阅读的业务内容 | 键盘与鼠标均不能触发写入 |
| projection unavailable | 平台状态与投影错误 | 不显示冒充当前结果的旧 nodeView，宿主必要入口仍可达 |
| 最小实际宿主高度 | 最后一行、提示、宿主动作区 | 滚动和 Tab 能到达主要操作，不被固定区遮挡 |
| 长文本/缺图/大金额 | 换行、对齐、全文与币种 | 不挤掉操作，不把截断信息当完整值 |

审查后的交付区分：已定位的问题、建议方案、待确认行为、已修复项以及实际验证证据。改善外观不能删除尚未理解的业务区或必要操作。
