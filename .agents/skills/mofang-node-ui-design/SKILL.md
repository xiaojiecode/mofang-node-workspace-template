# 节点面板设计

设计目标是让用户看清当前业务、理解等待原因并完成下一步。先读工作区 AGENTS 与项目本地规则，检查目标页面、现有截图/实际宿主和相邻业务。调整已有页面时保留未授权改变的展示、文案和交互。

落地实现默认先读 [Lit 组件库技能](../mofang-lit-ui/SKILL.md)，优先组合现有公共组件；只有已确认需求不能表达时才扩展库，用户明确指定的替代方案优先。

## 原型与界面边界

节点 UI 以原型和用户确认的交互为准。保留执行能力不等于必须展示通用面板。要求移除的区域不得搬入 Lit、公共组件、折叠区或其他位置继续保留。原型缺少必要操作时，先列出具体缺口与影响，确认后再实施。

不得自动附加任务列表、候选 JSON、技术 ID、协议状态、动作记录或通用控制区。区分执行语义不要求逐条常驻展示；已确认移除的区域不得换容器或换渲染框架保留。

## 先确定任务与页面边界

说明用户要完成的具体决定、需要比较的信息和操作后的真实结果。信息缺口先查已有 Schema、投影、组件与运行证据；重要页面行为和视觉方向需讨论确认。只读审查先给问题、证据和影响，不直接重设计。

settings 是宿主右侧内容区，business 是有限高度上拉抽屉；先核对实际可用尺寸和原型，再安排已确认内容。standard/full-panel 不作为自动增加共同宿主动作区的理由。不要设计独立站导航、全屏营销首屏或重复保存/取消按钮。

业务规则不清时先用 [业务设计技能](../mofang-node-business-design/SKILL.md) 确定；技术接线按 panels.json 选择 [Lit 面板技能](../mofang-lit-node/SKILL.md) 或 [低代码面板技能](../mofang-lowcode-node/SKILL.md)。低代码物料和配置以运行时目录为准，由 AI 操作、用户只预览。设计草案不能作为新接口已存在的证据。

## 组织信息与操作

- 首屏优先放当前对象/阶段、需要用户处理的原因、决定所需数据和下一步。进度、处理数量须来自真实事实，未知时不编百分比或估计耗时。
- 表单按用户决定分组，关键字段靠前，相关约束放字段旁；高级项仅在确有用途时渐进展开。标签持续可见，placeholder 不能代替标签；必填、默认值、单位和范围与 Schema 一致。
- 表格用于跨对象比较；详情用于理解单个对象。列优先服务本次判断，不照搬所有 JSON 字段。商品提供辨识信息，金额附币种、按小数语义展示并对齐；截断内容保留可达的全文入口。
- 筛选、排序、分页与选择需要核对能力和范围。尤其说清全选针对当前页还是全部结果、换页是否保留选择；这是行为决策，不能由 UI 自作约定。
- 一个操作区域突出当前主要动作，其余保持次级层级；按钮用稳定业务动词说明效果。破坏性或大范围操作按实际影响讨论确认交互，不给所有按钮机械加确认框。
- 已受理动作显示真实处理状态，避免连续点击产生额外提交；断线/结果未知提供查询与核对入口，不把“重试”当通用错误恢复。

## 视觉与空间

先检查 [现有 UI 导出](../../../lib/browser/ui/index.ts) 与 [主题样式](../../../lib/browser/ui/styles/theme.ts)，复用合适的组件、字体、间距和颜色变量。只有现有组件不能表达已确认需求时才扩展；单次布局不先抽通用组件库。

用清楚的标题、正文和辅助文字形成层级，以对齐、留白和分隔表达信息归属。密集数据优先保证可比较性；不要把每个字段包成卡片、给每个标题配装饰图标或用过量状态色争夺注意。新视觉方向围绕业务和宿主形成，不凭“高级感”替换现有主题。

在实际宿主高度内分配内容与动作空间，明确滚动容器；固定区域不得挡住末行、错误提示或键盘焦点。长标题、长 URL、中文、无图和大数值要能排版。按目标宿主范围检查尺寸，不默认扩展移动端重设计。

状态不能仅靠颜色表达；保留可见键盘焦点、可读文字与对比度，优先原生表单/按钮/表格语义。交互控件有可访问名称，错误关联到字段；对异步结果做适量可访问提示，避免每次订阅刷新抢焦点或重复播报。动画只解释变化，并尊重减少动态效果偏好。

## 状态更新与布局稳定

同一节点的后台订阅、重新核验和动作状态更新不得引起 UI 布局闪动。保留稳定的面板骨架、表格列、操作栏和行身份；权限或可操作状态变化优先切换禁用、文字与图标，不通过增删选择列或整块内容重建造成重排。加载图标与状态文字应有稳定占位，不能挤动相邻控件。

反馈消息不得突然推挤主要内容。结合实际宿主空间选择预留反馈区或独立状态区域，长消息与核对操作通过区域内滚动保持可达；新增占位对内容空间的影响需按项目规则确认。不能为避免闪动隐藏错误、保留已失去权限的数据，或用旧投影冒充当前结果；只有同一目标、仍可展示的数据才可在刷新期间保留，并明确标记核验状态、禁止不安全操作。

动画只用于用户主动展开、切页、查看详情等有意义的变化。普通订阅刷新不重播入场，不用高度或位移动画掩盖布局跳动；快速反向与减少动态效果偏好仍须正确。新对象到达或用户主动展开可以改变内容尺寸，但不能把状态提示的反复插入移除当成必要变化。

验证时在同一数据集上切换就绪、核验、处理中、失败与恢复，比较主区域位置和尺寸、列宽、滚动位置及 DOM 身份；普通刷新保留仍有效的焦点与草稿。还要在窄面板和较矮抽屉中检查固定区不能把表格挤到不可阅读，所有反馈和操作都能通过滚动、键盘到达。

## 数据与反馈必须诚实

只从 ready 的 composition 投影显示业务内容；unavailable 显示真实错误，不额外显示原始平台状态，不用旧缓存或 fixture 冒充当前结果。区分加载、无数据、筛选无匹配、失败、无权限与历史只读，它们的原因和可用下一步不同。

settings 编辑走宿主受控草稿，最终保存由宿主负责；空数字不转 0。浏览器局部状态仅承载交互，不用页面私有状态推进后台业务。

区分动作受理、applied、任务结果、候选处理与节点终态。部分失败在对应对象旁解释，汇总提示不覆盖逐项结果；过期修订保留可用输入并提示核对。页面切换与重开恢复用真实身份和动作记录，不自动重发 POST。

按需读 [面板评审场景](references/panel-review.md)，将状态与关键操作一起验收。

## 验证与交付

新页面或显著布局调整在真实宿主/受控预览检查：有限高度、滚动、主要操作可达、键盘顺序、长内容和关键数据状态。先集中检查，再修复发现的问题；仅有新改动或疑点时追加检查，不无限打磨。

编译与类型、截图、交互测试、真实 SDK/平台链路分别报告。截图不能证明按钮有效，fixture 不能证明真实数据接线。未能运行浏览器时写明限制；不宣称视觉验收通过。需要实际发布时沿 Lit 技能核对 surface、目标及修订，设计授权不自动扩大发布范围。
