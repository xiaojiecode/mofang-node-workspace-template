# 节点业务设计

先把业务条件和结果讲清楚，再选择节点结构。沿用已有 mf.node/1 契约，不借设计任务修改平台协议。读取工作区 AGENTS、AGENTS.local.md（若存在）、相关节点及真实能力 Schema。事实、用户已确认规则、建议和未知项分开表达。

## 从实际业务取证

沿输入到输出阅读 node.ts、contract.ts、run.ts、reducer、tasks、settings.ts、view.ts 与已有 fixture，只读取本任务相关文件。已有节点先理解为何这样处理，不从文件名推断完成情况。通过现有 CLI describe 和实际能力契约核对数据、许可及调用结果，不要求用户猜可查事实。

确定使用者、处理对象和成功结果：谁在什么条件下交付什么内容，下游需要什么，哪些情况要等待人工。把“自动优化”“一键完成”等目标拆成可观察的条件与结果，不自动补造业务规则。

对会改变结果的空白先调查再讨论：例如零结果是否允许结束、未选择是否代表丢弃、部分失败是否允许处理其它候选、金额边界怎样计算。已有确认不重复审批，简单字段修复不强制写整套方案。

## 规则与数据

按复杂度用短段落或决策表记录：条件、数据来源、规则、产出、失败/待核对结果。覆盖相等边界、缺省/null/空数组、合法零值和互斥条件；区分系统默认、用户配置与真实运行输入。

- 核对输入输出字段的真实类型、必填性、单位、精度和来源。金额的币种、舍入位置与阈值包含关系必须有依据；不按展示格式反推存储类型。
- 系统业务类型使用可信目录，辅助字段按现有双 Schema 表达；不修改内置 Product 等业务结构，不为未知字段编造兼容映射。
- 主流 items 是业务内容，缺省或空数组不产生后继任务。一次输入、一次任务结果、一个候选和整批运行是不同粒度，规则必须说明针对哪一个。
- 仅持久化后续事件或恢复真正需要的业务事实；可从事实推导的显示状态放只读 Project。状态槽采用稳定 key 与冻结 Schema，不复制一套平台执行状态。

## 映射到执行与人工交接

需要复杂状态时列出“事件、前置条件、读取事实、状态变化、计划命令、待结清事项”，用项目真实标识，不预设新 API 或固定状态枚举。实现细节读取相邻 [JS 技能](../mofang-js-node/SKILL.md)，不在设计中重定义 ABI。

- 函数绑定、reducer、updater、guard、Project 都不执行业务副作用；真实能力放子任务当前阶段，每阶段最多一次调用。
- 不把 setter 后的旧闭包快照当更新后事实；状态与命令耦合时用一次 reducer transition 表达。
- 人工动作说明操作者、参数 Schema、可用条件、页面入口和结果去向。权限/修订/来源由服务端继续校验，前端按钮隐藏不能代替校验。
- 动作受理、协调事务 applied、任务完成、候选处置和节点成功分别判断。生产结束只是事件末尾声明，不能替代待结清任务、候选、unknown 或控制账本。
- 普通业务失败不自动重发；未知结果保留原操作身份并查询、核对。刷新、重连、页面重渲染都不是新业务触发，不新增去重、步骤回用或副作用回放。
- 节点只能到达执行中、暂停、待处理、已完成、已取消、执行失败。执行中仅用于系统实际推进；每个人工等待点说明等待原因、解除条件、入口和结束/失败去向，呈现为待处理，不能因无人操作长期停在执行中。暂停与取消来自平台控制，节点只读响应。
- 部分成功必须说明哪些对象已完成、哪些仍待处理以及实际可用的后续操作；不把聚合成功提示覆盖逐项失败。

对人工筛选、审核和结束的具体推导，可按需读 [业务推导示例](references/review-example.md)。示例是假设性场景，不是平台能力或既定业务规则。

## 形成可实现的决定

复杂方案交付应能从业务规则追到字段/类型、事件/任务、候选/动作、页面及验证场景。列明涉及文件和现有能力缺口。契约、状态、恢复或交互存在重要取舍时，给可行选项、推荐理由与代价，标出“待确认决策”和暂停边界；确认前不实施依赖该决定的部分。

不为了“设计完整”新增模式框架、数据库、重试队列或通用配置层。遵守项目材料位置要求，不默认新建平行技术设计、PRD 或根目录说明文件。

## 按规则验证

把关键规则转成给定条件、触发事件、预期结果与禁止副作用的场景。优先覆盖边界、零结果、不选择、任务失败、unknown、过期动作、重复点击/刷新及节点切换，按具体改动选取，不给每个小改动套全量测试。

验证不能只断言状态字符串：检查真实命令/任务次数、输出内容与来源、候选处置、动作结果及未完成事项。mock 不证明真实能力已调用，类型通过不证明 Goja/平台运行成功。实施与验证接 [JS 技能](../mofang-js-node/SKILL.md)，界面交接接 [UI 设计技能](../mofang-node-ui-design/SKILL.md)。
